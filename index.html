Chapter Five — Rules, Systems, Consequences

One mistake could
break everything.

I wanted to understand what actually happens underneath a game. Movement. Collision. Timing. Rules. State.

Snake looks simple from the outside. Underneath, it's a loop that never stops asking the same question, many times a second: where is everything now, and did anything just go wrong?

The more I built, the more I wanted to understand what was underneath.

06
Chapter Six — The Other Player

If messages could
travel — could a game?

I wanted to take the idea of the chat application further. If messages could exist between people, could an entire game exist between them?

A real-time, multiplayer poker platform — chip counts, turn order, and side pots synced live across every connected player, with the actual game logic decided on the server so no client could quietly cheat.

Built with Socket.io for event-driven state sync and Supabase/PostgreSQL for persistent accounts and match history.

WebSockets Server-authoritative logic Turn management Multiple connected clients Disconnect handling

07
Chapter Seven — From Experiments to Engineering

Something other
people could use.

Eventually, my projects stopped being experiments. I had to build something larger. Something structured. Something that other people could actually use.

StriderDesk was my college final-year project — a project management and team collaboration tool. It was selected among the top FYP projects of the batch.

This was the point I started thinking like a software engineer instead of someone simply making projects.

The problem, first

A team needs one place to plan work, talk to each other, and see what's coming — Kanban boards for tasks, a shared calendar for meetings, and voice channels for the huddles that shouldn't need a separate app.

Kanban boards Role-based REST API JWT authentication Agora voice channels Team calendar

08
Chapter Eight — Now I Wanted to Push It

Four players.
One world. Real time.

After building applications, I wanted to challenge myself again. This time: multiple people, real-time movement, shooting, one shared world that has to feel the same to everyone in it at once.

Each match runs on its own isolated Cloudflare Durable Object instance. Player positions sync over raw WebSockets with server-authoritative health and respawns, smoothed with client-side interpolation so network jitter doesn't show. A custom 2D raycasting engine handles fog-of-war and line-of-sight, built from scratch.
